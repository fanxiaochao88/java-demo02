# 核心机制详解

## 一、JWT 认证机制

### 什么是 JWT？

JWT（JSON Web Token）是一种无状态的身份认证方案。

**传统 Session 方案的问题：**
- 服务器要存储每个用户的登录状态，占内存
- 多台服务器时，Session 不共享

**JWT 方案：**
- 服务器不存任何状态
- 登录成功后生成一个 token 给前端
- 前端每次请求都带上这个 token
- 服务器用密钥验证 token 是否合法，从中取出用户 ID

### JWT 的结构

一个 JWT 长这样（三段用 `.` 分隔）：
```
eyJhbGciOiJIUzI1NiJ9.eyJlbXBJZCI6MX0.xxxxx
   Header（算法）      Payload（数据）   Signature（签名）
```

- **Header**：声明签名算法（这里用 HS256）
- **Payload**：存放数据，这里存了 `empId`（员工ID）
- **Signature**：用密钥对前两段签名，防止篡改

### 代码里怎么用的

**生成 token（登录成功后）：**
```java
// EmployeeController.java:47-52
Map<String, Object> claims = new HashMap<>();
claims.put(JwtClaimsConstant.EMP_ID, employee.getId());  // 把员工ID放进去
String token = JwtUtil.createJWT(
        jwtProperties.getAdminSecretKey(),  // 密钥：itcast
        jwtProperties.getAdminTtl(),        // 过期时间：7200000ms = 2小时
        claims);
```

**验证 token（每次请求时）：**
```java
// JwtTokenAdminInterceptor.java:47-48
Claims claims = JwtUtil.parseJWT(jwtProperties.getAdminSecretKey(), token);
Long empId = Long.valueOf(claims.get(JwtClaimsConstant.EMP_ID).toString());
```

## 二、拦截器机制

### 拦截器的作用

在请求到达 Controller 之前做统一处理（验证登录、记录日志等）。

### 注册拦截器（WebMvcConfiguration.java:33-37）

```java
registry.addInterceptor(jwtTokenAdminInterceptor)
        .addPathPatterns("/admin/**")           // 拦截所有 /admin/ 开头的请求
        .excludePathPatterns("/admin/employee/login");  // 但登录接口不拦截（否则死循环）
```

### 拦截器执行流程

```
请求进来
    ↓
preHandle() 执行
    ↓ 返回 true → 放行，继续执行 Controller
    ↓ 返回 false → 拦截，不执行 Controller
```

`JwtTokenAdminInterceptor.preHandle()` 的逻辑：
1. 如果不是 Controller 方法（比如静态资源），直接放行
2. 从请求头取 token
3. 用密钥解析 token
4. 解析成功 → 返回 true（放行）
5. 解析失败（token 过期/伪造）→ 设置响应状态码 401，返回 false（拦截）

## 三、全局异常处理

### 没有全局异常处理时

每个 Controller 方法都要 try-catch，代码重复且丑陋：
```java
public Result login(...) {
    try {
        Employee e = employeeService.login(dto);
        ...
    } catch (AccountNotFoundException ex) {
        return Result.error(ex.getMessage());
    } catch (PasswordErrorException ex) {
        return Result.error(ex.getMessage());
    }
}
```

### 有了全局异常处理

Service 直接抛异常，Controller 不用 try-catch：
```java
// EmployeeServiceImpl.java - 直接抛，不管
if (employee == null) {
    throw new AccountNotFoundException(MessageConstant.ACCOUNT_NOT_FOUND);
}

// GlobalExceptionHandler.java - 统一在这里处理
@ExceptionHandler
public Result exceptionHandler(BaseException ex) {
    return Result.error(ex.getMessage());
}
```

### 异常继承体系

```
RuntimeException
    └── BaseException（基础业务异常）
            ├── AccountNotFoundException（账号不存在）
            ├── AccountLockedException（账号被锁定）
            ├── PasswordErrorException（密码错误）
            ├── LoginFailedException（登录失败）
            ├── DeletionNotAllowedException（不允许删除）
            └── ... 其他业务异常
```

`@ExceptionHandler` 捕获 `BaseException`，由于多态，所有子类异常都会被捕获。

## 四、统一返回结果 Result<T>

所有接口都返回同一格式，前端好处理：

```json
// 成功
{ "code": 1, "data": {...}, "msg": null }

// 失败
{ "code": 0, "data": null, "msg": "密码错误" }
```

`Result<T>` 是泛型类，`T` 是 data 的类型：
- `Result<EmployeeLoginVO>` → data 是员工登录信息
- `Result<String>` → data 是字符串
- `Result<PageResult>` → data 是分页数据

## 五、ThreadLocal 与 BaseContext

### 问题背景

一个 HTTP 请求从 Controller → Service → Mapper 是同一个线程。
有时候 Service 层需要知道"当前是哪个用户在操作"，但又不想把用户 ID 一层层传参数。

### ThreadLocal 的原理

ThreadLocal 是线程本地变量，每个线程有自己独立的副本，互不干扰：

```
线程A（用户1的请求）: threadLocal = 1
线程B（用户2的请求）: threadLocal = 2
```

### BaseContext 的用法

```java
// 拦截器里（解析 token 后）存入
BaseContext.setCurrentId(empId);

// Service 层取出（不需要传参）
Long currentUserId = BaseContext.getCurrentId();

// 请求结束后清除（防止内存泄漏）
BaseContext.removeCurrentId();
```

## 六、配置文件的多环境机制

### application.yml（主配置）

```yaml
spring:
  profiles:
    active: dev   # 激活 dev 环境
```

### application-dev.yml（开发环境配置）

```yaml
sky:
  datasource:
    host: localhost
    port: 3306
    database: sky_take_out
    username: root
    password: '123456'
```

主配置里用 `${sky.datasource.host}` 引用这里的值。

**好处：** 开发用 dev 配置，上线换成 prod 配置，只改 `active: prod`，不用改代码。

## 七、JacksonObjectMapper（日期格式化）

Spring Boot 默认的 Jackson 不认识 Java 8 的 `LocalDateTime`，会报错或输出奇怪格式。

`JacksonObjectMapper` 继承 `ObjectMapper`，注册了自定义的序列化/反序列化规则：

| 类型 | 格式 |
|------|------|
| `LocalDateTime` | `yyyy-MM-dd HH:mm` |
| `LocalDate` | `yyyy-MM-dd` |
| `LocalTime` | `HH:mm:ss` |

在 `WebMvcConfiguration` 里注册这个自定义 Mapper，替换掉默认的，全局生效。

## 八、Knife4j 接口文档

Knife4j 是 Swagger 的增强版，自动扫描所有 Controller 生成可视化接口文档。

配置在 `WebMvcConfiguration.java:45-57`：
```java
@Bean
public Docket docket() {
    return new Docket(DocumentationType.SWAGGER_2)
            .select()
            .apis(RequestHandlerSelectors.basePackage("com.sky.controller"))  // 扫描这个包
            .paths(PathSelectors.any())
            .build();
}
```

启动项目后访问：`http://localhost:8080/doc.html`

可以直接在页面上测试接口，不需要 Postman。
