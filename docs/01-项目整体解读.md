# 苍穹外卖项目整体解读

## 一、项目是什么

这是一个**外卖平台**，分两端：
- **商家 Web 端**（管理后台）：老板/员工用浏览器操作，管理菜品、订单、员工等
- **用户小程序端**：顾客用微信小程序点餐、下单、支付

## 二、Maven 多模块结构（这是你最懵的地方）

```
sky-take-out/          ← 父项目（只有 pom.xml，不写代码）
├── sky-common/        ← 公共模块：工具类、异常、常量
├── sky-pojo/          ← 数据模型：DTO、Entity、VO
└── sky-server/        ← 主服务：Controller、Service、Mapper、配置
```

### 为什么要拆模块？

入门项目所有代码放一起，项目大了之后：
- 代码混乱，找不到东西
- 不同模块可以被多个项目复用（比如 sky-common 的工具类）
- 编译时只重新编译改动的模块，更快

### 模块之间的依赖关系

```
sky-server 依赖 sky-common 和 sky-pojo
sky-pojo   依赖 sky-common（有时候）
sky-common 不依赖任何自己的模块
```

sky-server 的 pom.xml 里写了：
```xml
<dependency>
    <groupId>com.sky</groupId>
    <artifactId>sky-common</artifactId>
</dependency>
<dependency>
    <groupId>com.sky</groupId>
    <artifactId>sky-pojo</artifactId>
</dependency>
```
这就是"我要用你"的声明。

## 三、一次登录请求的完整流程

理解这个流程，整个项目就通了。

```
前端发请求
POST /admin/employee/login
Body: { "username": "admin", "password": "123456" }

         ↓
[JwtTokenAdminInterceptor] 拦截器
  → /admin/employee/login 被排除，直接放行

         ↓
[EmployeeController.login()]
  → 接收 EmployeeLoginDTO（username + password）
  → 调用 employeeService.login()

         ↓
[EmployeeServiceImpl.login()]
  → 调用 employeeMapper.getByUsername(username) 查数据库
  → 判断：用户不存在 → 抛 AccountNotFoundException
  → 判断：密码不对  → 抛 PasswordErrorException
  → 判断：账号被锁  → 抛 AccountLockedException
  → 都通过 → 返回 Employee 对象

         ↓
回到 EmployeeController
  → 用 JwtUtil.createJWT() 生成 token
  → 用 Builder 模式构建 EmployeeLoginVO
  → 返回 Result.success(employeeLoginVO)

         ↓
前端收到：
{
  "code": 1,
  "data": {
    "id": 1,
    "userName": "admin",
    "name": "管理员",
    "token": "eyJhbGciOiJIUzI1NiJ9..."
  }
}
```

之后前端每次请求都在请求头带上这个 token，拦截器验证通过才能访问。

## 四、三层架构（和入门项目一样，只是更规范）

| 层次 | 类 | 职责 |
|------|-----|------|
| Controller 层 | `EmployeeController` | 接收请求、返回响应，不写业务逻辑 |
| Service 层 | `EmployeeServiceImpl` | 写业务逻辑（验证密码、判断状态） |
| Mapper 层 | `EmployeeMapper` | 只管和数据库打交道 |

## 五、DTO / Entity / VO 的区别（这是新概念）

入门项目可能直接用 Entity 传来传去，这里做了区分：

| 类型 | 全称 | 用途 | 举例 |
|------|------|------|------|
| **Entity** | 实体类 | 和数据库表一一对应 | `Employee`（有 password 字段） |
| **DTO** | Data Transfer Object | 前端传给后端的数据 | `EmployeeLoginDTO`（只有 username+password） |
| **VO** | View Object | 后端返回给前端的数据 | `EmployeeLoginVO`（有 token，没有 password） |

**为什么不直接用 Entity？**
- 安全：不能把 password 返回给前端
- 灵活：前端传的字段和数据库字段不一定一样
- 清晰：一看类名就知道这个对象是干什么用的
