# 01 - 大陆 Java 后端面试形势与准备策略

> 本文按 2026 年前后中国大陆 Java 后端招聘常见要求整理。不同城市、公司规模、业务方向差异很大，具体仍以岗位 JD、面试官风格和公司技术栈为准。

## 1. 当前 Java 后端面试的总体特点

中国大陆 Java 后端岗位常见面试不再只考“会不会写 CRUD”。即使是初级岗位，面试官也通常会从下面几类能力里组合提问：

1. Java 基础：集合、异常、泛型、反射、Stream、IO。
2. JVM 和并发：内存区域、GC、类加载、线程池、锁、volatile、ThreadLocal。
3. Spring 体系：IOC、AOP、事务、Bean 生命周期、Spring Boot 自动配置。
4. 数据库：MySQL 索引、事务、锁、MVCC、SQL 优化、分页查询。
5. 缓存：Redis 数据结构、缓存一致性、穿透/击穿/雪崩、分布式锁。
6. 项目经验：业务链路、数据库设计、接口设计、异常处理、权限、日志、性能优化。
7. 场景题：高并发下单、重复提交、库存扣减、消息可靠性、接口幂等。
8. 工程能力：Git、Maven、Linux、部署、日志排查、接口文档、单元测试。

换句话说，初级面试的核心不是“架构多高级”，而是你能否把一个真实后端系统讲清楚。

## 2. 不同经验段的考察重点

### 2.1 实习和校招

重点看基础、学习能力和项目完整性。

常见问题：

1. Java 集合为什么 HashMap 查询快？
2. ArrayList 和 LinkedList 有什么区别？
3. Spring Boot 一个请求进来以后怎么走？
4. MyBatis 的 mapper 接口为什么不用写实现类？
5. MySQL 索引为什么能加速查询？
6. 你的项目有哪些表？订单表和订单明细表是什么关系？
7. 登录之后怎么识别用户身份？
8. 你在项目里遇到过什么 bug，怎么解决的？

准备策略：

1. 把项目链路讲得非常清楚。
2. 基础题不追求特别深，但不能只会背定义。
3. 至少准备 2 个项目难点和 2 个项目不足。
4. 手写题重点练字符串、数组、链表、HashMap 思路和简单 SQL。

### 2.2 初级和 1-3 年

重点看能不能独立做业务、处理常见线上问题。

常见问题：

1. Spring 事务什么情况下会失效？
2. Redis 和 MySQL 怎么保证缓存一致性？
3. 线程池核心参数怎么设置？
4. 慢 SQL 怎么排查？
5. MQ 如何保证消息不丢、不重复？
6. 接口重复提交怎么防？
7. 订单状态机怎么设计？
8. 项目里有没有做过优化？为什么这么优化？

准备策略：

1. 每个技术点都要能落到项目场景。
2. 不会的生产经验不要硬编，可以说“我当前项目是学习项目，但我知道生产上需要补哪些机制”。
3. 对 MySQL、Redis、Spring 事务要明显比校招准备得更深。
4. 准备一次“线上问题排查”的完整叙述，比如 Redis 缓存不一致、接口慢、订单重复提交。

### 2.3 3-5 年

重点看复杂问题拆解、稳定性、架构取舍和团队协作。

常见问题：

1. 高并发秒杀系统如何设计？
2. 分布式事务如何选型？
3. 大表怎么治理？
4. 服务雪崩如何治理？
5. 如何设计灰度发布和回滚？
6. 你负责过哪些核心模块？指标提升多少？
7. 如何推动一个跨团队技术方案落地？

如果你的经验还没到这个阶段，不建议在简历上写“高并发、微服务、分布式事务、亿级数据”这类词，否则面试官会按高级标准追问。

## 3. 常见面试流程

### 3.1 简历筛选

筛选重点：

1. 学校、专业、学历和毕业时间。
2. Java 后端技术栈是否匹配。
3. 项目是否像真实后端项目。
4. 简历是否有明显水分。
5. 技能关键词是否与岗位 JD 匹配。

简历建议：

1. 技能栈不要堆太多，只写能解释的。
2. 项目描述不要写“负责所有模块”，要写清楚“重点负责什么、解决什么问题”。
3. 项目亮点要能被追问，不要写自己讲不清的亮点。
4. 每个项目至少准备一张链路图、一张表关系图、一份优化清单。

### 3.2 一面

一面通常偏基础和项目真实性。

你要证明：

1. 项目不是只跑过，而是真的理解。
2. Java、Spring、MySQL、Redis 基础能过关。
3. 遇到不会的问题能合理分析，而不是直接沉默。

### 3.3 二面

二面通常偏项目深挖、场景题和工程判断。

你要证明：

1. 能发现项目里的问题。
2. 能提出靠谱的优化方案。
3. 能理解业务约束，不是一味堆技术。
4. 能把问题拆成接口、数据、并发、事务、缓存、消息几个层面。

### 3.4 HR 面

HR 面重点看稳定性、沟通、动机、薪资和入职时间。

不要轻视 HR 面。技术过了但表达出“只想短期跳板”“对岗位不了解”“薪资预期混乱”，也可能被拒。

## 4. 面试官最想确认的 8 件事

### 4.1 你是不是真的做过项目

验证方式：

1. 让你画项目架构。
2. 让你讲某个接口从请求到返回的全过程。
3. 问数据库表字段。
4. 问异常分支。
5. 问为什么这样设计。

准备方式：

1. 每个接口按 Controller、Service、Mapper、SQL、返回值梳理。
2. 每个业务模块准备一个“正常流程”和一个“异常流程”。
3. 记住核心表：用户、员工、分类、菜品、套餐、订单、订单明细、购物车、地址簿。

### 4.2 你是否理解基础原理

面试官问 HashMap，不是为了听“数组加链表加红黑树”这几个词，而是看你能否解释：

1. 为什么要 hash。
2. hash 冲突怎么处理。
3. 为什么容量通常是 2 的幂。
4. 扩容为什么影响性能。
5. 为什么并发下不能用普通 HashMap。

### 4.3 你是否能处理问题

比如接口突然变慢，较好的回答顺序是：

1. 先确认影响范围：单接口还是全站，单用户还是所有用户。
2. 看监控和日志：响应时间、错误率、CPU、内存、数据库连接池。
3. 定位外部依赖：MySQL、Redis、第三方接口。
4. 分析代码路径：是否 N+1 查询、是否全表扫描、是否锁竞争。
5. 临时止血：限流、降级、扩容、回滚。
6. 长期治理：索引、缓存、异步化、分页、压测。

### 4.4 你是否知道边界

面试里最危险的不是“不会”，而是把没做过的东西说得过满。

更稳的表达：

```text
我在当前项目里没有完整做过生产级 MQ，但我理解可靠消息大概需要考虑三个环节：
生产者发送确认、Broker 持久化、消费者手动 ack 和幂等处理。
如果放到订单支付场景，支付成功后发通知或更新积分，我会让消费端根据业务唯一键做幂等，避免重复消费导致重复加积分。
```

## 5. 技术栈准备地图

### 5.1 必备

1. Java 8 基础语法、集合、Stream、Optional、LocalDateTime。
2. Spring Boot 2.x 常用开发模式。
3. MyBatis XML、动态 SQL、分页。
4. MySQL 事务、索引、常见优化。
5. Redis 缓存基础。
6. Maven、Git、Postman/Apifox、Linux 基本命令。

### 5.2 加分

1. 线程池和异步任务。
2. Spring Cache 和 RedisTemplate 对比。
3. JWT 鉴权、拦截器、ThreadLocal。
4. WebSocket 实时通知。
5. 定时任务。
6. 接口幂等、重复提交、分布式锁。
7. Docker 部署。

### 5.3 谨慎写入简历

下面这些如果写了，面试官很可能深挖：

1. 微服务治理。
2. 分布式事务。
3. 高并发秒杀。
4. Kafka/RocketMQ/RabbitMQ 生产实践。
5. Elasticsearch。
6. Kubernetes。
7. JVM 调优。

如果只是了解，不要写“精通”。可以写“了解常见方案”或干脆不写。

## 6. 简历项目写法

弱写法：

```text
使用 Spring Boot + MyBatis 完成外卖系统，实现用户登录、菜品管理、订单管理、Redis 缓存等功能。
```

问题：太像课程描述，没有个人贡献，没有技术判断。

更好的写法：

```text
基于 Spring Boot + MyBatis 实现外卖后台和用户端接口，重点梳理了登录鉴权、订单状态流转、菜品/套餐管理、报表统计和 WebSocket 来单提醒等链路。
在项目中使用 JWT + 拦截器完成用户身份识别，使用 AOP + 自定义注解统一填充创建人、更新时间等审计字段；
针对菜品、套餐等读多写少数据引入 Redis/Spring Cache，并整理缓存删除策略和一致性风险；
围绕下单、支付、取消、催单等场景补充订单状态机和接口幂等优化方案。
```

这个写法的优势：

1. 有业务链路。
2. 有技术点。
3. 有自己的整理和优化。
4. 面试官可以自然追问。

## 7. 面试前准备清单

### 7.1 简历清单

1. 技能栈每个词都能解释。
2. 项目每个亮点都能讲 3 分钟。
3. 项目每个不足都能讲改进方案。
4. 所有时间线真实一致。
5. 不写自己完全没接触过的技术。

### 7.2 项目清单

1. 能画三层架构。
2. 能画登录鉴权链路。
3. 能画订单下单链路。
4. 能画订单状态流转。
5. 能画 Redis 缓存读写链路。
6. 能解释事务边界。
7. 能解释哪些地方可能并发不安全。

### 7.3 技术清单

1. Java：HashMap、ArrayList、String、异常、反射、Stream。
2. JVM：内存区域、GC、类加载、双亲委派、OOM 排查。
3. 并发：线程池、锁、volatile、ThreadLocal、ConcurrentHashMap。
4. Spring：IOC、AOP、事务、Bean 生命周期、自动配置。
5. MySQL：索引、事务、锁、MVCC、慢 SQL。
6. Redis：数据结构、缓存一致性、分布式锁。

## 8. 常见失败原因

1. 项目只会照着简历念，一追问就不知道表结构和代码位置。
2. 技术题只背关键词，讲不出为什么。
3. 过度包装，写了高并发、微服务、分布式事务但答不上来。
4. 不会承认边界，明明没做过还硬说做过。
5. 表达混乱，回答没有层次。
6. 不知道自己项目的不足和改进方向。

## 9. 面试表达训练方法

每天选 3 个问题，按下面格式写答案：

```text
问题：
一句话结论：
核心原理：
项目联系：
常见坑：
如果继续追问，我还能讲：
```

写完以后闭卷口述，并录音回听。你会很快发现自己是“知道”还是“能讲清楚”。
