# 10 - HR 面、行为面、反问与模拟面试评分表

> 复习目标：技术面过后，不要在 HR 面、行为面和反问环节丢分。准备稳定、真实、不过度包装的表达。

## 1. HR 面主要看什么？

HR 面通常关注：

1. 求职动机。
2. 稳定性。
3. 沟通表达。
4. 薪资预期。
5. 入职时间。
6. 对岗位和公司的理解。
7. 是否有明显风险，比如频繁跳槽、目标不清、抗压差。

HR 面不一定问很深的技术，但会判断你是否适合团队。

## 2. 自我介绍怎么说？

### 1 分钟模板

```text
您好，我叫 XXX，主要方向是 Java 后端开发。
我熟悉 Java 基础、Spring Boot、MyBatis、MySQL、Redis 等常用后端技术。
最近重点做了一个外卖业务后端项目，包含管理端和用户端接口，覆盖员工、菜品、套餐、订单、报表、登录鉴权、Redis 缓存和 WebSocket 通知等模块。
在项目中我重点梳理了订单下单和状态流转、JWT 鉴权、AOP 自动填充、缓存一致性这些链路。
我目前希望找一份 Java 后端开发岗位，继续提升业务开发、数据库优化和系统稳定性方面的能力。
```

### 注意

1. 不要太长。
2. 不要背得像机器人。
3. 技术关键词要能被追问。
4. 最后要自然落到应聘岗位。

## 3. 为什么选择 Java 后端？

### 回答模板

```text
我选择 Java 后端主要有三个原因。
第一，Java 后端在企业系统里应用广，生态成熟，学习路径比较清晰；
第二，我对业务数据如何从接口进入系统、经过校验、事务、缓存、数据库再返回结果比较感兴趣；
第三，我做外卖项目时发现后端不只是写 CRUD，还要考虑权限、事务、缓存一致性、性能和异常处理，这些问题比较吸引我。
所以我希望继续在 Java 后端方向深入。
```

## 4. 你的优点是什么？

### 回答模板

```text
我觉得我的优点是学习后会主动整理和复盘。
比如做外卖项目时，我没有只把功能跑通，而是把登录鉴权、订单下单、Redis 缓存、AOP 自动填充这些链路单独整理成笔记。
遇到问题时，我也会尽量从日志、代码链路和数据变化去定位，而不是只看表面报错。
```

### 注意

优点要配例子，不要只说“认真负责、学习能力强”。

## 5. 你的缺点是什么？

### 回答模板

```text
我目前的不足是生产级项目经验还不够多。
比如高并发、复杂分布式事务、线上故障处理这些，我更多是通过学习和项目改造思路来理解，还没有特别多真实线上经验。
所以我现在会优先把 Java 基础、MySQL、Redis、Spring 事务和项目链路打扎实，同时补测试、日志和排查能力。
```

### 不要这么说

1. “我太追求完美。”
2. “我没有缺点。”
3. “我不太喜欢沟通。”
4. “我抗压能力不行。”

缺点要真实，但不能直接击中岗位底线。

## 6. 为什么离职或为什么换工作？

如果是应届或实习，可以改成“为什么看新机会”。

### 回答模板

```text
我希望找一个更贴近 Java 后端业务开发的岗位。
我目前已经系统学习了 Spring Boot、MyBatis、MySQL、Redis，并通过外卖项目梳理了订单、缓存、鉴权这些链路。
接下来希望在真实团队里参与更完整的需求开发、接口设计、问题排查和系统优化。
```

如果已有工作经历，不要攻击前公司。可以围绕业务方向、成长空间、技术匹配度表达。

## 7. 你能接受加班吗？

### 回答模板

```text
我能接受项目关键节点或线上问题导致的合理加班。
但我也会关注效率和计划，尽量通过提前沟通、拆分任务、及时暴露风险来减少无效加班。
如果团队确实有阶段性压力，我会配合把事情完成。
```

### 讲解

这个回答表达了配合度，也没有把自己说成无条件透支。

## 8. 你的薪资期望是多少？

### 准备方式

1. 先了解目标城市、学历、经验、岗位范围。
2. 给区间，不要只给一个死数。
3. 表达“可根据岗位职责和整体 offer 沟通”。

### 回答模板

```text
我目前期望是 X 到 Y。
这个范围是结合我对当前城市 Java 后端岗位、自己的项目能力和学习情况评估的。
当然我也会综合考虑岗位职责、团队技术栈、培养空间和整体福利。
```

### 注意

不要在完全不了解岗位前频繁强调薪资，也不要说“随便”。“随便”会显得你没有预期，也不专业。

## 9. 你未来 1-3 年规划是什么？

### 回答模板

```text
短期我希望先成为能独立负责业务模块的 Java 后端开发，熟练完成接口设计、数据库设计、业务开发、测试和问题排查。
中期我希望在 MySQL 优化、Redis 缓存、消息队列、系统稳定性方面继续深入，能处理更复杂的业务场景。
我不会一开始就追求很虚的架构能力，而是希望先把业务开发和工程基本功打扎实。
```

## 10. 项目遇到过什么困难？

### 回答模板：Redis 缓存一致性

```text
我在梳理菜品和套餐缓存时发现，缓存不是简单加一层 Redis 就结束。
如果更新数据库后不处理缓存，用户可能看到旧数据；
如果先删除缓存再更新数据库，并发下也可能把旧数据重新写回缓存。
所以我整理的方案是优先采用先更新数据库、再删除缓存，并设置 TTL 兜底。
如果删除失败，可以通过重试或 MQ 补偿。
这个过程让我意识到技术点要结合数据一致性来看。
```

### 回答模板：订单事务

```text
下单接口一开始看起来只是插入订单，但仔细梳理后发现它涉及订单主表、订单明细、购物车清空，后续还可能有库存和优惠券。
如果不加事务，中间任何一步失败都会造成数据不一致。
所以我把它理解为一个事务边界问题，并进一步思考了重复提交、订单号唯一和支付回调幂等。
```

## 11. 和同学或团队有分歧怎么办？

### 回答模板

```text
我会先确认分歧点是需求理解不同、技术方案不同，还是优先级不同。
如果是技术方案，我会尽量用事实比较，比如复杂度、风险、维护成本、性能和上线时间。
如果短时间无法完全统一，我会尊重负责人决策，并把风险和后续验证方式说清楚。
```

## 12. 反问面试官问什么？

建议问和岗位、团队、成长相关的问题。

可以问：

1. 这个岗位主要负责哪些业务模块？
2. 团队目前主要技术栈是什么？Spring Boot、MyBatis、Redis、MQ 使用情况如何？
3. 新人入职后一般从什么类型的需求开始做？
4. 团队如何做代码评审和测试？
5. 当前业务系统最关注的技术挑战是什么，比如性能、稳定性、数据一致性还是交付效率？
6. 如果有幸加入，您建议我提前补哪些技术？

谨慎问：

1. “会不会经常加班？”可以问，但不要一上来问。
2. “多久涨薪？”不适合技术面刚结束就问。
3. “你们公司稳不稳定？”表达太直接。

更好的问法：

```text
我想了解一下团队目前的迭代节奏，以及线上稳定性保障主要是怎么做的？
```

## 13. 技术面反问模板

```text
我想请教一下，如果以我今天的面试表现来看，您觉得我在 Java 后端方向最需要优先补强的是哪一块？
```

这个问题很实用。它能让你获得反馈，也体现你愿意成长。

## 14. 行为面 STAR 法则

STAR：

1. Situation：背景。
2. Task：任务。
3. Action：行动。
4. Result：结果。

### 示例

问题：你遇到过什么困难？

回答：

```text
背景：我做外卖项目订单模块时，发现下单不是单表插入。
任务：我需要保证订单主表、订单明细和购物车数据一致。
行动：我梳理了下单链路，明确事务边界，并进一步分析重复提交和支付回调幂等。
结果：我能把订单模块从简单 CRUD 讲成状态流转、事务一致性和接口幂等的完整链路。
```

## 15. 模拟面试评分表

每项 1-5 分：

| 维度 | 1 分 | 3 分 | 5 分 |
| --- | --- | --- | --- |
| 自我介绍 | 混乱、超时 | 能说明基本情况 | 清晰、有技术重点、有岗位匹配 |
| 项目讲解 | 像背简历 | 能讲功能 | 能讲链路、问题、优化 |
| Java 基础 | 只会关键词 | 能解释常见题 | 能讲原理和坑 |
| Spring | 只会使用注解 | 能讲 IOC/AOP/事务 | 能讲代理、失效、项目落地 |
| MySQL | 只会 CRUD | 能讲索引事务 | 能结合 SQL 优化和表设计 |
| Redis | 只会 set/get | 能讲缓存问题 | 能讲一致性、锁、项目策略 |
| 并发 | 概念混乱 | 能讲线程池和锁 | 能讲风险、排查和使用边界 |
| 场景题 | 不会拆解 | 能给简单方案 | 能讲取舍、风险、兜底 |
| 手写题 | 写不出 | 能写基础题 | 代码清晰，能讲复杂度 |
| 沟通表达 | 答非所问 | 基本清楚 | 结构化、真实、有边界 |

总分建议：

1. 40 分以下：先别急着大量投递，基础和项目表达都要补。
2. 40-60 分：可以投递实习/初级，但要持续复盘。
3. 60-80 分：初级面试比较稳，重点补短板。
4. 80 分以上：表达和技术都较稳，可以冲更匹配的岗位。

## 16. 模拟面试题单

### 第一轮：项目真实性

1. 介绍一下你的项目。
2. 你负责哪个模块？
3. 下单接口怎么实现？
4. 登录态怎么维护？
5. Redis 在项目里怎么用？
6. 这个项目有哪些不足？

### 第二轮：技术基础

1. HashMap 底层原理。
2. ArrayList 和 LinkedList 区别。
3. Spring 事务失效场景。
4. MySQL 索引为什么快？
5. Redis 缓存穿透怎么解决？
6. 线程池核心参数。

### 第三轮：场景题

1. 用户重复点击下单怎么办？
2. 支付回调重复通知怎么办？
3. 菜品缓存和数据库不一致怎么办？
4. 订单列表查询很慢怎么排查？
5. WebSocket 多实例怎么推送？
6. MQ 消息重复消费怎么办？

### 第四轮：HR 和行为

1. 为什么选择 Java 后端？
2. 你的优缺点是什么？
3. 遇到困难怎么解决？
4. 你未来规划是什么？
5. 薪资期望是多少？
6. 你有什么想问我的？

## 17. 面试后复盘模板

每场面试结束后立即记录：

```text
公司/岗位：
面试轮次：
面试时长：
被问到的项目问题：
被问到的技术问题：
没答好的问题：
面试官追问方向：
我表达混乱的地方：
需要补的知识：
下次改进：
```

复盘比盲目刷题更重要。你会发现不同公司反复问的其实是同一批核心问题。

## 18. 最后提醒

面试不是背诵比赛。真正有效的准备是：

1. 项目能画图。
2. 链路能复述。
3. 技术点能解释原因。
4. 不足能说改进。
5. 不会的点能承认边界，并给出合理分析。

做到这些，初级 Java 后端面试会稳很多。
