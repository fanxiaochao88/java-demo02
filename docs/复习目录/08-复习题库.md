# 08 - 复习题库

这份题库采用“问题 + 参考答案 + 解析”的形式。
建议先遮住答案自己说一遍，再看参考答案补漏。

## 使用方法

1. **第一遍**：只看问题，口头回答。
2. **第二遍**：看参考答案，补齐关键词。
3. **第三遍**：回到代码里找对应类和方法。
4. **第四遍**：用自己的话讲一遍完整链路。

## 一、项目架构

### 1. 苍穹外卖项目整体分为哪两端？

**参考答案：**

- 管理端：商家员工使用，用来管理员工、分类、菜品、套餐、订单、报表等。
- 用户端：微信小程序用户使用，用来浏览商品、管理地址、购物车、下单、支付等。

**解析：**

这不是两个后端项目，而是一套后端接口通过路径区分两端：`/admin/**` 和 `/user/**`。

### 2. 项目为什么要拆成 `sky-common`、`sky-pojo`、`sky-server` 三个模块？

**参考答案：**

- `sky-common` 放公共代码，如工具类、常量、异常、统一返回值。
- `sky-pojo` 放数据对象，如 Entity、DTO、VO。
- `sky-server` 放真正的服务端业务代码，如 Controller、Service、Mapper、配置类。

**解析：**

拆模块的目的不是让项目复杂，而是让职责更清晰。公共能力和业务对象可以复用，主服务只关注业务流程。

### 3. Controller、Service、Mapper 分别负责什么？

**参考答案：**

- Controller：接收请求、绑定参数、返回结果。
- Service：处理业务逻辑、业务校验、对象组装。
- Mapper：执行数据库访问。

**解析：**

新手常见错误是把业务逻辑写进 Controller，或者让 Mapper 承担业务判断。这个项目基本按三层架构组织代码。

### 4. DTO、Entity、VO 有什么区别？

**参考答案：**

- DTO：前端传给后端的数据对象。
- Entity：和数据库表结构对应的实体。
- VO：后端返回给前端的展示对象。

**解析：**

不要直接拿 Entity 做所有入参和出参。比如员工登录返回不能把密码字段返回给前端，所以需要 `EmployeeLoginVO`。

### 5. 一次普通接口请求大概经过哪些环节？

**参考答案：**

```text
前端请求 -> 拦截器鉴权 -> Controller -> Service -> Mapper -> MySQL -> Service组装结果 -> Controller返回Result
```

**解析：**

复习项目时不要逐个类孤立看，要按请求链路看。链路比单个知识点更重要。

## 二、Spring Boot 和 Spring MVC

### 6. `@SpringBootApplication` 有什么作用？

**参考答案：**

它是 Spring Boot 启动类核心注解，包含组件扫描、自动配置等能力，让项目能通过 `SpringApplication.run(...)` 启动。

**解析：**

可以粗略理解为：从启动类所在包开始扫描，把 Controller、Service、Mapper、配置类等交给 Spring 管理。

### 7. `@RestController` 和 `@Controller` 有什么区别？

**参考答案：**

`@RestController` 等价于 `@Controller + @ResponseBody`，方法返回值会直接序列化成 JSON。

**解析：**

前后端分离项目通常使用 `@RestController`。如果返回页面模板，才更多用 `@Controller`。

### 8. `@RequestMapping`、`@GetMapping`、`@PostMapping` 怎么理解？

**参考答案：**

- `@RequestMapping`：通用请求映射。
- `@GetMapping`：只处理 GET 请求。
- `@PostMapping`：只处理 POST 请求。

**解析：**

类上通常写公共路径，如 `/admin/employee`；方法上写具体路径，如 `/login`。

### 9. `@RequestBody`、`@PathVariable`、`@RequestParam` 分别用于什么参数？

**参考答案：**

- `@RequestBody`：接收 JSON 请求体。
- `@PathVariable`：接收路径变量，如 `/order/{id}`。
- `@RequestParam`：接收查询参数或表单参数。

**解析：**

例如 `@RequestBody OrdersSubmitDTO dto` 用于下单；`@PathVariable Long id` 用于查询订单详情。

### 10. `@DateTimeFormat(pattern = "yyyy-MM-dd")` 的作用是什么？

**参考答案：**

把请求中的日期字符串转换成 Java 的 `LocalDate`。

**解析：**

报表接口里经常用它接收 `begin` 和 `end` 参数。

## 三、登录鉴权

### 11. 管理端登录流程是什么？

**参考答案：**

```text
前端提交用户名密码 -> EmployeeController -> EmployeeServiceImpl.login -> 查询员工 -> 校验密码和状态 -> 生成JWT -> 返回EmployeeLoginVO
```

**解析：**

登录接口本身会被拦截器排除，因为此时用户还没有 token。

### 12. 用户端微信登录流程是什么？

**参考答案：**

```text
前端传code -> 后端调用微信接口换openid -> 查询用户 -> 不存在则注册 -> 生成JWT -> 返回UserLoginVO
```

**解析：**

用户端不保存微信密码，核心身份标识是微信返回的 `openid`。

### 13. JWT 在项目中解决什么问题？

**参考答案：**

JWT 用来标识用户登录状态。登录成功后服务端签发 token，前端后续请求带 token，服务端解析 token 判断当前用户是谁。

**解析：**

JWT 不是数据库，也不是 Session。它是一个带签名的令牌。

### 14. 管理端和用户端 token 有什么区别？

**参考答案：**

- 管理端 header 名是 `token`，claims 中保存 `empId`。
- 用户端 header 名是 `authentication`，claims 中保存 `userId`。

**解析：**

这也是为什么项目里有两个拦截器：`JwtTokenAdminInterceptor` 和 `JwtTokenUserInterceptor`。

### 15. 拦截器 `preHandle` 返回 `true` 和 `false` 分别代表什么？

**参考答案：**

- `true`：放行，请求继续进入 Controller。
- `false`：拦截，请求不会继续执行。

**解析：**

token 校验失败时，项目设置响应状态码 `401`，然后返回 `false`。

### 16. 为什么拦截器里要把用户 id 存到 `BaseContext`？

**参考答案：**

为了让后续业务代码能方便获取当前登录用户 id，比如下单、查询个人订单、自动填充创建人。

**解析：**

`BaseContext` 底层使用 `ThreadLocal`，它能在当前请求线程里保存用户 id。

### 17. 为什么请求结束后要调用 `BaseContext.removeCurrentId()`？

**参考答案：**

因为 Web 服务器线程会复用。如果不清理，可能导致下一个请求拿到上一个用户的 id。

**解析：**

这是 `ThreadLocal` 的常见风险：用完必须清理。

## 四、MyBatis 和数据库

### 18. MyBatis 的 Mapper 接口和 XML 是怎么对应的？

**参考答案：**

XML 文件里的 `namespace` 对应 Mapper 接口全限定名，SQL 标签的 `id` 对应接口方法名。

**解析：**

例如 `EmployeeMapper.xml` 的 `namespace="com.sky.mapper.EmployeeMapper"`，`<select id="pageQuery">` 对应 `pageQuery` 方法。

### 19. `#{}` 和 `${}` 有什么区别？

**参考答案：**

- `#{}` 是预编译参数，占位符方式，能防 SQL 注入。
- `${}` 是字符串拼接，风险更高。

**解析：**

业务查询条件一般用 `#{}`。只有动态表名、排序字段等特殊场景才谨慎考虑 `${}`。

### 20. `<where>` 标签有什么作用？

**参考答案：**

自动补 `where`，并处理开头多余的 `and` 或 `or`。

**解析：**

动态查询条件不确定时，`<where>` 能让 SQL 更安全、简洁。

### 21. `<set>` 标签有什么作用？

**参考答案：**

用于动态更新字段，自动处理最后多余的逗号。

**解析：**

编辑员工、编辑菜品、更新订单状态时，都适合用 `<set>`。

### 22. `PageHelper.startPage(page, pageSize)` 要放在哪里？

**参考答案：**

要放在真正执行查询语句之前。

**解析：**

PageHelper 通过拦截后续第一个查询 SQL 实现分页。如果放错位置，分页不会生效。

### 23. 为什么订单表和订单明细表要分开？

**参考答案：**

一个订单可以包含多个菜品或套餐，这是典型的一对多关系。订单主表保存订单整体信息，订单明细表保存每个商品项。

**解析：**

如果把所有商品塞进订单表，会导致字段不固定、查询困难、扩展性差。

## 五、AOP、注解和反射

### 24. `@AutoFill` 解决了什么问题？

**参考答案：**

自动填充公共字段，如创建时间、修改时间、创建人、修改人。

**解析：**

这些字段很多表都有，如果每个 Service 都手写，会重复且容易漏。

### 25. `@Target(ElementType.METHOD)` 表示什么？

**参考答案：**

表示这个注解只能标在方法上。

**解析：**

`@AutoFill` 是标在 Mapper 方法上的，所以目标类型是 `METHOD`。

### 26. `@Retention(RetentionPolicy.RUNTIME)` 表示什么？

**参考答案：**

表示注解在运行时仍然存在，可以被反射读取。

**解析：**

AOP 中需要读取 `@AutoFill` 的 `value()`，所以必须保留到运行时。

### 27. AOP 切入点表达式 `execution(* com.sky.mapper.*.*(..))` 怎么理解？

**参考答案：**

表示匹配 `com.sky.mapper` 包下任意类的任意方法，参数任意。

**解析：**

再配合 `@annotation(com.sky.annotation.AutoFill)`，就只拦截带 `@AutoFill` 的 Mapper 方法。

### 28. 项目里的反射主要用来做什么？

**参考答案：**

通过方法名动态调用实体对象的 setter 方法，实现公共字段自动填充。

**解析：**

例如动态调用 `setUpdateTime(LocalDateTime)`，不用关心具体实体类是员工、菜品还是分类。

### 29. 反射有什么缺点？

**参考答案：**

- 编译期不容易发现方法名错误。
- 运行时才可能报错。
- 性能比直接调用低。

**解析：**

学习项目里使用反射很好，但真实项目里要控制使用范围。

## 六、缓存、Redis 和 Spring Cache

### 30. Redis 在外卖项目中适合缓存哪些数据？

**参考答案：**

适合缓存访问频率高、变化不太频繁的数据，比如店铺状态、分类下的菜品列表、套餐列表等。

**解析：**

缓存的目标是减少数据库压力，不是替代数据库。

### 31. Spring Cache 的核心思想是什么？

**参考答案：**

用注解声明缓存逻辑，让业务代码不用手动写大量 Redis 读写。

**解析：**

常见注解包括 `@Cacheable`、`@CachePut`、`@CacheEvict`。

### 32. 为什么修改菜品或套餐后要清理缓存？

**参考答案：**

否则用户端可能继续看到旧数据，造成缓存和数据库不一致。

**解析：**

缓存不是只会提升性能，也会带来一致性问题。

## 七、订单业务

### 33. 用户下单的核心流程是什么？

**参考答案：**

```text
校验地址 -> 查询购物车 -> 创建订单 -> 批量插入订单明细 -> 清空购物车 -> 返回订单提交结果
```

**解析：**

这个链路是项目最重要的业务链路之一，建议能脱口而出。

### 34. 为什么下单时要先校验地址和购物车？

**参考答案：**

地址为空无法配送，购物车为空无法生成订单。这些都是业务前置条件。

**解析：**

Service 层最重要的职责之一就是做业务校验。

### 35. 订单状态有哪些？

**参考答案：**

- `1`：待付款
- `2`：待接单
- `3`：已接单
- `4`：派送中
- `5`：已完成
- `6`：已取消

**解析：**

这些状态定义在 `Orders` 实体中，订单业务围绕状态流转展开。

### 36. 用户取消订单时为什么要判断订单状态？

**参考答案：**

因为不是任何状态都能随便取消。待付款、待接单阶段可以取消；如果已经接单或配送中，就需要限制。

**解析：**

订单状态机的核心就是：不同状态允许的操作不同。

### 37. “再来一单”是怎么实现的？

**参考答案：**

查询原订单明细，把每个订单明细转换成购物车记录，再批量插入购物车。

**解析：**

这里体现了对象转换：`OrderDetail -> ShoppingCart`。

### 38. 支付成功后为什么要通过 WebSocket 通知管理端？

**参考答案：**

因为管理端需要实时知道有新订单，不能一直靠刷新页面。

**解析：**

HTTP 是请求响应模式，WebSocket 更适合服务端主动推送。

## 八、报表、定时任务和 Excel

### 39. 报表统计为什么经常先生成日期列表？

**参考答案：**

为了保证每一天都有数据位置。即使某天没有订单，也要补 `0`，否则前端图表横轴和数据会对不上。

**解析：**

这也是项目里多次把数据库查询结果转换成 `Map<LocalDate, ...>` 的原因。

### 40. 营业额统计为什么只统计已完成订单？

**参考答案：**

因为只有已完成订单才算真实有效营业额。待支付、已取消订单不能计入。

**解析：**

统计口径比 SQL 写法更重要。先明确业务口径，再写查询。

### 41. `LocalDateTime.of(begin, LocalTime.MIN)` 有什么作用？

**参考答案：**

把某天转换成当天开始时间，比如 `2026-07-17 00:00:00`。

**解析：**

查询某个日期范围时，需要把日期转换为具体时间范围。

### 42. 定时任务在项目中做了什么？

**参考答案：**

- 定时取消超时未支付订单。
- 定时处理派送中但长时间未完成的订单。

**解析：**

这类任务不是由用户请求触发，而是系统按时间自动执行。

### 43. `@Scheduled(cron = "0 * * * * ?")` 大概表示什么？

**参考答案：**

表示每分钟执行一次。

**解析：**

项目中用它定时处理超时未支付订单。

### 44. POI 在项目里用来做什么？

**参考答案：**

读取 Excel 模板，填充运营数据，然后通过响应输出流下载给前端。

**解析：**

核心类包括 `XSSFWorkbook`、`XSSFSheet`、`XSSFRow`。

## 九、文件上传和 WebSocket

### 45. 文件上传接口的核心流程是什么？

**参考答案：**

```text
Controller接收MultipartFile -> Service生成唯一文件名 -> 上传到COS -> 返回文件访问URL
```

**解析：**

项目里主线实现用的是 Tencent COS，不是阿里云 OSS。

### 46. 为什么上传文件要用 UUID 生成文件名？

**参考答案：**

为了避免不同用户上传同名文件时互相覆盖。

**解析：**

保留原始扩展名是为了让图片、文件类型能正确识别。

### 47. WebSocket 的 `@ServerEndpoint("/ws/{sid}")` 表示什么？

**参考答案：**

定义 WebSocket 连接地址，并通过 `{sid}` 区分不同客户端连接。

**解析：**

服务端可以根据 sid 保存不同客户端的 Session。

### 48. 为什么 `WebSocketServer` 中的 `HashMap` 建议改成 `ConcurrentHashMap`？

**参考答案：**

因为多个客户端可能同时连接、断开或接收消息，普通 `HashMap` 不是线程安全的。

**解析：**

这是一个典型的并发安全优化点。

## 十、代码质量和优化思考

### 49. 为什么不建议长期保留 `allow-circular-references: true`？

**参考答案：**

它会允许循环依赖存在，掩盖代码结构问题。

**解析：**

更好的做法是调整类之间的依赖关系，让依赖方向清晰。

### 50. 为什么不推荐在业务代码里到处写数字状态值？

**参考答案：**

数字本身不可读，容易写错。应该使用常量或枚举表达状态含义。

**解析：**

比如 `Orders.COMPLETED` 比直接写 `5` 更清楚。

### 51. 为什么全局异常处理比 Controller 里到处 `try-catch` 更好？

**参考答案：**

它能统一错误返回格式，减少重复代码，让 Controller 更专注于请求入口。

**解析：**

Controller 层越薄，项目越容易维护。

### 52. 为什么 `WebMvcConfigurationSupport` 要谨慎继承？

**参考答案：**

继承它会接管 Spring Boot 的部分 MVC 自动配置，可能影响默认静态资源、消息转换器等行为。

**解析：**

如果只是加拦截器，很多场景用 `WebMvcConfigurer` 更轻量。

### 53. 如果你要优化这个项目，前三个最值得改的点是什么？

**参考答案：**

可以优先考虑：

1. 合并或抽象 Admin/User 两套 JWT 拦截器重复逻辑。
2. 把 WebSocket 会话容器改成线程安全集合。
3. 逐步去掉循环依赖配置，理清 Bean 依赖关系。

**解析：**

优化不要一上来大改，优先改风险明确、收益明显、影响范围可控的点。

## 十一、综合复述题

### 54. 请完整复述“员工登录后访问管理端接口”的链路。

**参考答案：**

员工先调用登录接口提交用户名密码。后端查询员工表，校验账号、密码和状态。校验通过后生成 JWT 返回给前端。前端后续访问 `/admin/**` 接口时，在请求头中携带 token。管理员拦截器解析 token，拿到 `empId`，存入 `BaseContext`，然后放行请求。Controller 调用 Service，Service 调用 Mapper 访问数据库，最后通过 `Result` 统一返回。

**解析：**

这个题能测出你是否理解 Controller、Service、Mapper、JWT、拦截器、ThreadLocal、Result 的关系。

### 55. 请完整复述“用户下单”的链路。

**参考答案：**

用户登录后携带 token 访问下单接口。用户端拦截器解析 token，把 `userId` 放入 `BaseContext`。下单 Service 先校验地址是否存在，再按当前用户查询购物车。如果购物车为空就抛业务异常。校验通过后创建订单主表记录，再把购物车商品转换为订单明细并批量插入，最后清空购物车，返回订单编号、金额和下单时间。

**解析：**

这个题能测出你是否理解订单主表、订单明细表、购物车和当前用户上下文的关系。

### 56. 请完整复述“报表统计”的链路。

**参考答案：**

管理端传入开始日期和结束日期。Controller 用 `@DateTimeFormat` 接收日期参数，调用 ReportService。Service 先生成日期列表，再把日期转成开始时间和结束时间，调用 Mapper 做数据库聚合查询。查询结果转成 Map，按日期列表补齐没有数据的日期，最后拼接成前端 ECharts 需要的字符串并封装成 VO 返回。

**解析：**

报表功能的关键不是 SQL，而是“统计口径 + 日期补齐 + VO 格式适配”。

### 57. 请说明这个项目最核心的五个技术点。

**参考答案：**
