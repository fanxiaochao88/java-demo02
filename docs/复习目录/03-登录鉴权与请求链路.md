# 03 - 登录鉴权与请求链路

## 1. 为什么要单独讲登录

这个项目的主线不是“登录”，而是**登录后整条请求链路怎么跑**。
只要把登录和鉴权看明白，后面的员工、用户、订单、报表接口都容易理解。

## 2. 管理端登录流程

### 流程

1. 前端发 `POST /admin/employee/login`
2. `EmployeeController` 接收 `EmployeeLoginDTO`
3. `EmployeeServiceImpl.login()` 查询员工
4. 校验账号是否存在、密码是否正确、账号是否禁用
5. 生成 JWT
6. 返回 `EmployeeLoginVO`

### 关键代码

```java
Map<String, Object> claims = new HashMap<>();
claims.put(JwtClaimsConstant.EMP_ID, employee.getId());
String token = JwtUtil.createJWT(
        jwtProperties.getAdminSecretKey(),
        jwtProperties.getAdminTtl(),
        claims);
```

### 你要记住的点

- 管理端 token 的 header 名是 `token`
- 令牌里存的是 `empId`
- 登录接口本身不能被拦截器拦住，所以要在拦截器里排除

## 3. 用户端登录流程

用户端不是用户名密码登录，而是微信小程序登录：

1. 前端拿到微信 `code`
2. 后端调用微信接口换 `openid`
3. 如果用户不存在，就自动注册
4. 返回用户 token

### 关键代码

```java
String openId = getOpenId(userLoginDTO.getCode());
User user = userMapper.getByOpenId(openId);
if (user == null) {
    user = User.builder()
            .openid(openId)
            .createTime(LocalDateTime.now())
            .build();
    userMapper.insert(user);
}
```

### 用户端和管理端的区别

| 项目 | 管理端 | 用户端 |
|---|---|---|
| 登录方式 | 用户名 + 密码 | 微信 code |
| token header | `token` | `authentication` |
| claims | `empId` | `userId` |
| 拦截器 | `JwtTokenAdminInterceptor` | `JwtTokenUserInterceptor` |

## 4. JWT 语法

### 生成 token

```java
String jwt = JwtUtil.createJWT(secretKey, ttlMillis, claims);
```

### 解析 token

```java
Claims claims = JwtUtil.parseJWT(secretKey, token);
Long userId = Long.valueOf(claims.get(JwtClaimsConstant.USER_ID).toString());
```

### 你要理解的本质

- JWT 不是加密数据库
- JWT 只是把一些声明信息签名后发给客户端
- 客户端下次请求带回 token，服务端校验签名是否有效

## 5. 拦截器怎么工作

`HandlerInterceptor` 的核心方法是 `preHandle`：

```java
public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception {
    if (!(handler instanceof HandlerMethod)) {
        return true;
    }

    String token = request.getHeader(jwtProperties.getAdminTokenName());
    Claims claims = JwtUtil.parseJWT(jwtProperties.getAdminSecretKey(), token);
    Long empId = Long.valueOf(claims.get(JwtClaimsConstant.EMP_ID).toString());
    BaseContext.setCurrentId(empId);
    return true;
}
```

### `afterCompletion`

请求结束后一定要清理线程变量：

```java
public void afterCompletion(...) {
    BaseContext.removeCurrentId();
}
```

## 6. ThreadLocal 在这里干什么

`BaseContext` 的作用是**把当前登录人的 id 临时放到线程里**，让后续 Service / Mapper 能拿到。

```java
public class BaseContext {
    public static ThreadLocal<Long> threadLocal = new ThreadLocal<>();
}
```

### 典型使用场景

- 自动填充创建人、修改人
- 下单时拿当前用户 id
- 订单列表只查当前用户的数据

## 7. 这条链路最该背下来的话

> 登录成功后，token 只是“通行证”；真正决定当前用户是谁的是拦截器里的 `BaseContext`。
