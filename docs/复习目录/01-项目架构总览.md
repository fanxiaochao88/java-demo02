# 01 - 项目架构总览

## 1. 这个项目做什么

苍穹外卖是一个外卖系统，分成两端：

- **管理端**：员工登录后管理菜品、套餐、订单、报表、员工信息
- **用户端**：用户通过微信登录，浏览商品、加购物车、下单、支付、看历史订单

这类项目的核心不是“页面多”，而是**把请求、业务、数据、缓存、消息、定时任务串起来**。

## 2. Maven 多模块结构

```text
sky-take-out/        父项目，只负责聚合
├── sky-common/      公共工具、常量、异常、统一返回值
├── sky-pojo/        实体类、DTO、VO
└── sky-server/      启动类、Controller、Service、Mapper、配置
```

### 每个模块的职责

- `sky-common`：放跨模块复用的代码，避免重复
- `sky-pojo`：放业务对象，统一实体和传输对象
- `sky-server`：放真正的业务入口和运行逻辑

## 3. 分层方式

项目基本遵循下面的链路：

```text
Controller -> Service -> Mapper -> MySQL
               |
               ├-> Redis / WebSocket / 定时任务 / 文件存储
               └-> DTO / VO / Result / Exception
```

### 各层职责

| 层 | 作用 | 典型类 |
|---|---|---|
| Controller | 接收参数，返回结果，不写重业务 | `EmployeeController`、`OrderController` |
| Service | 写业务逻辑、做校验、拼装对象 | `EmployeeServiceImpl`、`OrderServiceImpl` |
| Mapper | 只做数据库访问 | `EmployeeMapper`、`OrderMapper` |
| Entity | 对应数据库表 | `Employee`、`Orders` |
| DTO | 前端传来的数据 | `EmployeeLoginDTO`、`OrdersSubmitDTO` |
| VO | 返回给前端的数据 | `EmployeeLoginVO`、`OrderVO` |
| Config/Interceptor/Aspect | 通用能力 | `WebMvcConfiguration`、`JwtTokenAdminInterceptor`、`AutoFillAspect` |

## 4. 一次请求是怎么走的

以员工登录为例：

1. 前端请求 `/admin/employee/login`
2. `JwtTokenAdminInterceptor` 放行登录接口
3. `EmployeeController.login()` 接收 `EmployeeLoginDTO`
4. `EmployeeServiceImpl.login()` 查询数据库并校验账号、密码、状态
5. `JwtUtil.createJWT()` 生成 token
6. Controller 组装 `EmployeeLoginVO`
7. 返回 `Result.success(...)`

### 代码骨架

```java
@RestController
@RequestMapping("/admin/employee")
public class EmployeeController {

    @PostMapping("/login")
    public Result<EmployeeLoginVO> login(@RequestBody EmployeeLoginDTO dto) {
        Employee employee = employeeService.login(dto);
        String token = JwtUtil.createJWT(...);
        return Result.success(EmployeeLoginVO.builder()
                .id(employee.getId())
                .userName(employee.getUsername())
                .token(token)
                .build());
    }
}
```

## 5. 这个项目最重要的设计点

- **前后端分离**：后端只返回 JSON，不直接返回页面
- **管理端和用户端分流**：`/admin/**` 和 `/user/**` 两套接口
- **统一返回值**：所有接口都包在 `Result<T>` 里
- **统一异常处理**：业务异常集中处理，不在每个 Controller 里写 `try-catch`
- **统一身份识别**：JWT + 拦截器 + `ThreadLocal`

## 6. 复习时要先记住的三个问题

2. 为什么要区分 `DTO`、`Entity`、`VO`？
3. 为什么登录后还要带 token，为什么要拦截器？
